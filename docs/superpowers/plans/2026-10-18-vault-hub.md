# Vault Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unraid composes one published vault from the Mac and BigRig source vaults, gates it, and pushes it to `AIMDaAlien/Obsidian-Vault`; the Mac stops publishing.

**Architecture:** A stdlib-plus-PyYAML Python package `composelib` in the public repo's `.github/scripts/` does the composition (tree, frontmatter, curation, links, publish). A thin CLI `compose.py` orchestrates one run. On Unraid a wrapper script runs the CLI inside a small container from cron against the exclusive cache share `/mnt/cache/vault`. Syncthing delivers the sources receive-only. Curation and ranks are content edits in the Mac vault plus `curation.yml`.

**Tech Stack:** Python 3.12 in the `ghcr.io/astral-sh/uv:python3.12-bookworm` image plus git; PyYAML for the two config files only; `unittest`; Syncthing REST API; Unraid 7 cron under `/boot/config/plugins/dynamix/`; GitHub deploy key.

**Spec:** `docs/superpowers/specs/2026-10-18-vault-hub-design.md` (read it first; this plan argues from it).

## Global Constraints

- Source vaults are never written by code or by hand on Unraid: `/sources` is mounted read-only (spec 5.1).
- No job path under `/mnt/user`; the hub is `/mnt/cache/vault` (spec 3, 4.1).
- `compose.py` and `composelib/` are public; no secrets, hostnames, LAN addresses, or home paths in code, tests, fixtures, or commit messages. Placeholders per `Redaction Conventions.md`.
- Python: stdlib only inside `composelib`, except `yaml` (PyYAML) in `config.py` and `notes.py` for `compose.yml` and `curation.yml`. Note frontmatter is edited textually, never through a YAML library (round-trip safety).
- Tests use `unittest`, discovered by `python -m unittest discover -s .github/scripts/tests -t .github/scripts` as the existing workflow does.
- Protected published paths, verbatim: `.github/`, `.gitignore`, `README.md`, `garden-manifest.json`, `curation.yml`.
- Excluded extensions, verbatim: `json jsonl log csv py sh patch txt exit-code`. Excluded dirs: `_inbox`, `.obsidian`, `.trash`. Image extensions: `png svg jpg jpeg gif webp`.
- `summary` at most 160 characters. Featured ranks are positive integers, unique across both sources.
- Commit message on publish: `vault publish: <YYYY-MM-DD HH:MM> (m5pro N notes, bigrig M notes)`.
- Work on the public repo happens in a throwaway clone in the scratchpad, never in the live Mac vault, which auto-pushes. Set `git config core.hooksPath .github/hooks` in the clone so the privacy gate runs on commit.
- Live systems (Mac vault, Unraid, Syncthing) are touched only in Tasks 6 to 9, with the verification steps written there.

## Review Focus

1. A note whose frontmatter has `featured:` with a non-integer value (`featured: yes`, `featured: "3"`): curation validation must report it, not crash or silently rank it. Test in Task 2.
2. A wikilink inside a Markdown table written as `[[Target\|alias]]`: the link rewriter must leave the escape intact and still resolve the target. Test in Task 3.
3. Two notes in different source folders embed images with the same bare filename (`report.png` twice): resolution must refuse (ambiguous) and report both paths, not pick one. Test in Task 3.
4. A source folder that exists but is empty because Syncthing has not finished its first sync: the empty-source guard must fail before any deletion is planned. Test in Task 1.
5. A previous run committed but its push failed (network): the next run must fail "remote diverged" rather than reset and lose that commit. Test in Task 4.

Links without a file extension (note links) are never touched.

### Task 4: Publish pipeline and CLI

**Files:**
- Create: `.github/scripts/composelib/publish.py`, `.github/scripts/compose.py`, `.github/scripts/tests/test_compose_publish.py`

**Interfaces:**
- Consumes everything from Tasks 1 to 3.
- Produces `syncthing_idle(api: str, api_key: str, folder_ids: list[str]) -> tuple[bool, str]` (urllib, 5 s timeout; any error is `(False, reason)`).
- Produces `fast_forward(repo: Path) -> str` returning the new HEAD; raises `ComposeError("remote diverged: ...")` when HEAD is not an ancestor of `origin/main` (Review Focus 5); uses `git fetch origin main` then `git merge-base --is-ancestor HEAD origin/main` then `git reset --hard origin/main`.
- Produces `run_gate(repo: Path) -> tuple[bool, str]` running `python .github/scripts/privacy-gate.py` with cwd `repo` after `git add -A`; on failure runs `git reset` and returns the gate output.
- Produces `commit_and_push(repo: Path, message: str, push: bool) -> str | None` (returns commit hash or None when the index is clean).
- Produces `RunReport` dataclass (`timestamp, status, counts: dict[str,int], added, changed, removed, unresolved: list[str], unwrapped: list[str], gate: str, commit: str | None, duration_s: float, reason: str`), `write_report(md_path, json_path, report)`, `read_last_counts(json_path) -> dict[str,int]`, `notify(reason: str)` (calls `/usr/local/emhttp/webGui/scripts/notify -i warning -s "vault publish" -d <reason>` when that file exists, else logs).
- CLI `compose.py --config PATH [--no-push] [--dry-run] [--skip-syncthing-check] [--curation PATH] [--report-dir PATH]`. Exit 0 on publish, no-op, or sources busy; 1 on any failure; 2 on bad arguments. `--dry-run` composes into `published`, runs the gate, prints `git diff --stat`, then `git reset --hard` and `git clean -fd` restore the clone. Order of a run is spec 5.2 steps 1 to 9; curation is copied to `published/curation.yml` before the gate.
